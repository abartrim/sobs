Setup Guide

Channels define where notifications are sent. Supported types:

  • webhook — HTTP POST to any URL with optional custom headers and body template. Use {{summary}} in the body template for the alert message.
  • slack — Post to a Slack Incoming Webhook URL.
  • email — Send via SMTP. Supports STARTTLS. Credentials are stored in the database; use environment-level secrets management for production deployments.
  • browser_push — Web Push notifications to browsers. Requires SOBS_VAPID_PRIVATE_KEY (base64url-encoded DER PKCS#8 P-256 private key) set as an environment variable. Generate a key pair with POST /api/notifications/vapid-keygen.

Rules define when to send notifications. Each rule has one or more conditions matched against recent signal averages from v_derived_signals_1m. Use ANY (OR) or ALL (AND) logic to combine conditions. A cooldown prevents re-firing until the configured interval has elapsed.

Triggering: Call POST /api/notifications/check periodically (e.g., every minute via cron) to evaluate all enabled rules and dispatch notifications.

Browser Push Key Generation: Call POST /api/notifications/vapid-keygen to generate a new VAPID key pair. Copy the private_key value and set it as SOBS_VAPID_PRIVATE_KEY in your environment, then restart SOBS. The public_key is used by the browser's pushManager.subscribe().
