# `internal/otlp/genpb` — vendored OTLP protobuf message types

Generated Go types for the OpenTelemetry Protocol (OTLP) `Export{Logs,Trace,Metrics}ServiceRequest`
messages and their transitive dependencies (common / resource / logs / trace / metrics). Used by the
OTLP-protobuf ingest path (`/v1/{logs,traces,metrics}` with `Content-Type: application/x-protobuf`).

## Why vendored instead of a module dependency

The dependency policy (`go/DEPENDENCIES.md`) keeps the only new module to the protobuf **runtime**,
`google.golang.org/protobuf`. Depending on `go.opentelemetry.io/proto/otlp` directly would also pull
in gRPC, grpc-gateway and genproto — none of which this server needs (it never speaks gRPC). So the
message-only `.pb.go` files are vendored here; the `*_grpc.pb.go` service stubs are deliberately
**not** copied (they are the only files that import gRPC).

These files register the OTLP proto file descriptors in the global protobuf registry at `init`. They
are the only copy in the binary (the upstream module is not imported anywhere), so there is no
double-registration.

## Provenance / how to regenerate

Source: `go.opentelemetry.io/proto/otlp@v1.10.0` (Apache-2.0; see `LICENSE`). That module pins
`google.golang.org/protobuf v1.36.11`, which is the version `go.mod` requires.

The files are the upstream generated `.pb.go` verbatim, with one mechanical change: the inter-package
import path is rewritten from the upstream module path to ours. To reproduce:

```sh
OTLP=$(go env GOMODCACHE)/go.opentelemetry.io/proto/otlp@v1.10.0
DEST=go/internal/otlp/genpb
for f in \
  common/v1/common.pb.go resource/v1/resource.pb.go \
  logs/v1/logs.pb.go metrics/v1/metrics.pb.go trace/v1/trace.pb.go \
  collector/logs/v1/logs_service.pb.go \
  collector/metrics/v1/metrics_service.pb.go \
  collector/trace/v1/trace_service.pb.go
do
  mkdir -p "$DEST/$(dirname "$f")"
  sed 's|go.opentelemetry.io/proto/otlp|github.com/sobs/sobs/internal/otlp/genpb|g' "$OTLP/$f" > "$DEST/$f"
done
cp "$OTLP/LICENSE" "$DEST/LICENSE"
gofmt -w "$DEST"   # upstream was generated by protoc-gen-go v1.26.0; reflow doc comments for this toolchain
```

The proto package names embedded in the descriptors (`opentelemetry.proto.*`) are unchanged, so
`protojson` still emits canonical OTLP-JSON — which is exactly how the protobuf ingest path re-renders
a decoded message into the map the JSON row builders consume (`cmd/sobs/otlp_proto.go`).
